The tool follows a Producer-Consumer architecture. The main thread iterates through the file system (Producer) and populates an `asyncio.Queue`. A pool of worker tasks (Consumers) pulls file paths from the queue. Each worker offloads blocking I/O (file reading) to a thread pool via `run_in_executor`, while the regex matching logic remains in the async context. This ensures the event loop remains responsive and that the tool can maximize disk throughput and CPU utilization simultaneously.
